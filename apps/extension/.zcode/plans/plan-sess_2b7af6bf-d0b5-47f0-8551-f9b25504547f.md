# 简谱视图：双模式（真旋律 + 和弦推算兜底）

## Context

新增第三个面板视图「Jianpu」：歌词 ↔ 简谱对照。调研后采用**双模式数据策略**：

- **旋律模式（准确）**：在现有 local-companion Docker 管线加旋律提取阶段（Spotify **basic-pitch**, Apache-2.0, CPU ONNX），输出 note events（onset/offset/MIDI/置信度）→ 结合已有 madmom beats 量化为标准时值 → **JianpuRender**（Apache-2.0, npm `jianpurender`）渲染标准简谱 SVG（级数+八度点+下划线/附点/延音线/休止+调号拍号+歌词对齐+播放高亮）
- **和弦推算模式（兜底）**：视频未重分析、无 melodyData 时，逐词标注和弦级数+唱名+简单时值（word end - start 量化），立即覆盖全部已缓存视频，徽章标注「推算」

零破坏：companion 阶段失败不影响主流程（镜像 downbeats 的容错模式）；扩展侧默认 OFF、增量 else-if；数据库字段 additive。

## 第一部分：companion 旋律阶段（Python）

### 1. 新增 `apps/local-companion/engine/process_melody.py`
- `extract_melody(wav_file)`: basic-pitch `predict()` → note events `[{pitch_midi, start, end, confidence}]`
- 清洗：置信度阈值过滤；输出紧凑打包格式（镜像 `_madmom_beats_to_downbeat_payload` 的逗号串风格，main.py:582）：`{"notes": "start_s.dur_ms.midi.conf,...", "engine": "basic-pitch"}`（时间 3 位小数）
- 失败返回 None，绝不失败整个 job

### 2. `apps/local-companion/engine/main.py`（`process_wav_file`:653 起）
- 仿 `DOWNBEATS_ENABLED`（main.py:33）加 `MELODY_ENABLED = env YOUCHORDS_MELODY 默认开`
- 管线顺序：Chordino 之后加 `melody_payload = extract_melody(wav_file)`（~794 行结果 dict 加 `melody=melody_payload`）
- requirements 加 `basic-pitch`（CPU 推理默认走 ONNX/TF-Lite，无 torch 依赖）

## 第三部分：jianpuChartView.js（核心新文件，~1100 行）

镜像 measureChartView.js 骨架（IIFE + `/* yc-module-scope */` + 私有工具函数复制约定）：

- 常量：`SYNC_KEY='jianpuViewEnabled'`；`LOCAL_KEY_PREFIX='yc_jianpu_'` 存 `{ tonicOverride, modeOverride, solfegeRow, durationMarks }`
- `onContentRendered(combinedData, authoritativeChords, container)`（镜像 measureChartView.js:953）：extractData 取 lines/words/sections/beatsData；额外读 `melodyData`（currentSongData / pullChordsFromDb 兜底路径都要带出）；无任何和弦时 pullChordsFromDb
- **调性解析**：chords 拼 `t:Chord` → `window.ycKeyEstimator.estimateKeyFromChordText()`（已导出）；工具栏下拉手动覆盖（12 主音+大小调），按视频持久化；小调用歌本惯例 1=关系大调
- **级数换算**（共用）：`midi → pc`，`degree=(pc-tonicPc+12)%12` 映射大调音阶 `[0,2,4,5,7,9,11]`；八度 = MIDI 区间（旋律模式可算出真正的高低八度点）；非自然音 ♯/♭ 前缀
- **旋律模式渲染**：melodyData.notes → JianpuRender JSON（`start/length` 用 madmom beats 或估 BPM 换算成拍，`pitch` 用 MIDI，`lyrics` 用逐词时间轴，`keySignature`=1=X）；加载 `vendor/jianpurender.iife.js` 经 `window.ycLoader.js()`；实例化 `JianpuSVGRender` 到面板容器；用其 note 高亮/`onNoteClick` API 接播放同步（`updateHighlight` → 按时间换算拍位置）与点击跳转
- **推算模式渲染**（无 melodyData）：单次 innerHTML + scrollTop 保持（同 measureChartView.js:598 模式）；每词 = 上「级数+时值记号+小字唱名」下「词文本」；和弦切换处 inline chip（和弦名+级数，经 `getCapoChord→chordRenderer.getDisplayChordName`）；间奏行只渲染 chip；时值 = 词时长 vs 拍长量化（≥1.75拍 `—`／1.25-1.75 附点／0.75-1.25 裸数字／0.375-0.75 单下划线／<0.375 双下划线／空隙≥1拍 `0`），工具栏「时值」开关
- 两种模式统一：工具栏（调性下拉、时值开关、唱名开关、模式徽章「旋律/推算」）、段落头（Intro/Verse…）、词点击 → `video.currentTime = t - subtitleOffset()`、自动滚动走 `autoScrollWanted()`、`yc:timeUpdate`(isScrubbing) 即时高亮、预览面板转发
- 全局监听 once：`yc:panelClosing` 清态、capo/移调事件 rebuild（镜像 measureChartView.js:911-946）
- `window.toggleJianpuView`（镜像 measureChartView.js:1004）：开启联动关 Measure+TAB；导出 `window.ycJianpu={isEnabled,toggle,onContentRendered,updateHighlight,onPanelClosing}`；init 读 sync 键镜像 `window.jianpuViewEnabled`
- `ensureCss()`：`<style id="yc-jianpu-chart-style">`，含时值记号/八度点样式、sepia/light/rtl 主题

## 验证

1. `node --check` 新文件与全部改动 JS；companion 容器重建后单测 `extract_melody` 对一段 wav 输出 note events（含时长达 <100ms 误差的抽验）
2. **旋律模式**：companion 重分析一个视频 → IndexedDB 出现 melodyData → 开 Jianpu：标准简谱（八度点/下划线/延音线/休止/调号 1=X）、歌词对齐无重叠、播放高亮跟随、点音符跳转；对照已知旋律的歌抽验音高正确率
3. **推算模式**：不重分析的旧视频 → 推算渲染 + 「推算」徽章；C 大调歌核对 C=1/F=4/G=5/Am=6m；时值档位合理、可关
4. 互斥开关来回切换、关闭后原歌词视图完整恢复；Capo/移调下和弦名变而级数正确；无字幕视频 chip 时间轴；console 无新增报错；老版本 payload/旧 DB 记录回归正常（无 melodyData 字段不报错）
