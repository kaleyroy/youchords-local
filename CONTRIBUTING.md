# Contributing

Thank you for helping build YouChords Local.

## Before opening a pull request

1. Open an issue for substantial architecture or UX changes.
2. Keep processing local and bind companion services to `127.0.0.1` only.
3. Do not add accounts, subscriptions, fingerprinting, hosted analytics, or
   mandatory cloud services.
4. Do not commit secrets, cookies, user data, copyrighted test media, model
   files with incompatible terms, or tools intended to bypass access controls.
5. Include focused tests and update documentation for behavior changes.

## Development priorities

The current priorities are listed in `docs/LOCAL_FIRST_ROADMAP.md`. The first
usable milestone is a local companion that processes a user-owned audio file
and returns the packed YouChords chord schema.

## Commit and pull request style

- Keep commits focused and describe behavior, not implementation trivia.
- Explain what changed, why, how it was tested, and any remaining limitations.
- Keep unrelated formatting or generated-file changes out of the pull request.
